Implementation Steps

6 VMs • 3 Clouds • HA Pairs • Cloud-Native Secrets
SECTION DETAILED STEPS
1. Prerequisites (Common)
  1. 1Obtain EfficientIP SOLIDserver licenses and virtual appliance images (VHD/OVA/qcow2).
  2. 2Prepare SSH key pair solid-key and admin user admin.
  3. 3Ensure Equinix Fabric Cloud Router BGP peering is pre-staged (ASN 64512, VIP 10.100.100.100/32).
  4. 4Install Terraform 1.5+ locally.
  5. 5Open required ports: UDP/TCP 53, TCP 179 (BGP), TCP 443 (SOLIDserver console).
  6. 6Cloud-native secrets management (new):
    • Azure: Create Key Vault + Managed Identity (grant VM access to secret)
    • AWS: Create Secrets Manager secret + IAM Role for EC2
    • GCP: Create Secret Manager secret + Service Account with Secret Accessor role
  7. 7Store SSH private key and admin credentials in the respective cloud secret store. Reference in Terraform via data sources (azurerm_key_vault_secret, aws_secretsmanager_secret_version, google_secret_manager_secret_version).
2. Deploy SOLIDserver Primary Appliance
  • Deploy the SOLIDserver primary virtual appliance in the corporate hub (Azure East US 2 recommended).
  • Download latest SOLIDserver image from EfficientIP customer portal and upload to each cloud.
  • Run initial setup → join to AD domain corp.root if required.
  • Access console at https://solid-primary.corp.example.com.
6. Azure East US 2 Deployment (HA Pair)

DNS Subnet: 192.168.16.0/24

  1. Create resource group rg-solid-dns-prod-eastus2.
  2. Upload SOLIDserver VHD as custom image.
  3. Deploy 2× SOLIDserver VMs (solid-dns-eff-az-01 / solid-dns-eff-az-02) using custom image.
  4. Secrets: Use azurerm_key_vault_secret data source to retrieve SSH key; inject via admin_ssh_key in Terraform.
  5. Add secondary private IP 10.100.100.100/32 to each VM NIC.
  6. Configure NSG: Allow UDP/TCP 53, TCP 179 (BGP), SSH 22.
  7. SSH as admin (key from Key Vault) and run FRR/BGP config.
7. AWS us-east-2 Deployment (HA Pair)

DNS Subnet: 192.168.20.0/24

  1. Import SOLIDserver AMI.
  2. Deploy 2× SOLIDserver VMs (solid-dns-eff-aws-01 / solid-dns-eff-aws-02).
  3. Secrets: Use aws_secretsmanager_secret_version data source + IAM Role to retrieve SSH key; inject via user_data or cloud-init.
  4. Assign secondary private IP 10.100.100.100.
  5. SSH as admin (key from Secrets Manager) and apply FRR/BGP config.
8. GCP us-east4 Deployment (HA Pair)

DNS Subnet: 192.168.30.0/24

  1. Import SOLIDserver custom image.
  2. Deploy 2× SOLIDserver VMs (solid-dns-eff-gcp-01 / solid-dns-eff-gcp-02).
  3. Secrets: Use google_secret_manager_secret_version data source + Service Account; inject SSH key via metadata.
  4. Configure alias IP range 10.100.100.100/32.
  5. SSH as admin (key from Secret Manager) and apply FRR/BGP config.
